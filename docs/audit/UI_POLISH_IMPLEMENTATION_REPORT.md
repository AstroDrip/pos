# UI Polish: Implementation Report

Date: 2026-11-06. Branch `feature/owner-tools`. Audit: `docs/audit/UI_VISUAL_AUDIT.md`.

No business logic was changed. The only behaviour change is a safety fix: the recurring-expense form no longer pre-selects the capital "Equipment" category (E1).

## 1. Initial findings (summary)

| Severity | Count | Main items |
|---|---|---|
| Critical | 1 | At 1024 px the top bar overflowed: controls spilled off the bar, the user name was invisible, the page scrolled sideways (S1) |
| High | 7 | Bar about 130 px tall with wrapped labels (S2); illogical tab order (S3); no page titles (S5); raw status codes in the customer filters (C1); wrapping tile values (C2); oversized purchase sub-navigation (U1); Admin cards squeezed and inputs clipped (A1); recurring form defaulting to a capital category (E1) |
| Medium | 14 | Nested cards; uneven tiles; tall table rows from full-size buttons; empty tables without a message; two date formats; whole report rows painted red; low-contrast disabled buttons in dark mode; and others |

## 4. Design system changes (`src/renderer/styles.css`, one stylesheet)

- **Kept:** the existing brand and palette (green primary, dark top bar), the light/dark colour tokens and the theme architecture. No new palette and no gradients.
- **Added scale tokens:**
  - spacing `--sp-1…6` (4/8/12/16/24/32);
  - radius `--r-sm/md/lg/pill` (4/6/8);
  - type `--fs-xs…total` (12/13/14/15/18/22/34);
  - control heights 36 and 28 (small);
  - top bar height.
- **Controls:**
  - buttons, inputs and selects share one height;
  - row buttons inside tables are automatically small;
  - checkboxes are no longer stretched;
  - disabled buttons are neutral grey (readable in both themes) instead of a faded primary.
- **Tables:**
  - one header style (smaller, semibold, tinted);
  - consistent row padding and hover;
  - right-aligned tabular numbers that never wrap;
  - an `actions` cell that does not wrap;
  - an empty-state row.
- **Tiles:**
  - equal minimum height;
  - values never wrap (ellipsis plus a tooltip if too long);
  - a small variant for dates.
- **Status badges:** unchanged meanings; sizes aligned to the scale.
- **Motion:** only colour transitions on buttons, enabled only when the operating system allows motion (`prefers-reduced-motion`). Nothing moves in the till.
- **Direction:** logical properties (`inset-inline`, `margin-inline-start`) are used in the new rules.

## 5. Shared components

- **`PageHeader`** (new): title, one-line description, actions at the end. Used on Refund, Customers, Stock, Products, Purchases, Expenses, Accounting, Reports and Admin. The Sell screen deliberately has no header, so the cashier keeps the space.
- **`EmptyRow`** (new): explains why a table is empty. Used in Stock on hand, Expenses, Recurring expenses and the Reports tables.
- **`.subpanel`:** flat sections inside an account page, replacing cards inside cards (Receive a payment, Use the advance, Credit settings).
- **`.seg`:** segmented control for sub-sections and filters (Purchases sections, Customers accounts/ageing, invoice filters).
- **`.grid-cards`:** responsive grid with cards at least 340 px wide (Admin, Stock, Products).
- **`StatusBadge`:** now also exports `statusLabel`, so filters use the same words as the badges.

## 6. Screen by screen

| Screen | Changes |
|---|---|
| **Shell** | One 48 px bar: brand, tabs grouped by workflow with thin separators (Sell, Refund, Customers · Stock, Products, Purchases · Expenses, Accounting, Reports · Shift, Admin), then the utilities. The backup status is a dot plus one line. The bar stays visible when scrolling. Below 1280 px everything is more compact and the user name is hidden. Below 1100 px the tabs move to a second row, so none are hidden |
| **Sell** | Visible label on the customer box; one-line keyboard hint; second-language product name aligned under the main name; compact rows and inputs in the cart; totals lines styled. Shortcuts, focus behaviour and the scanner path are untouched (the real-app test covers them) |
| **Customers** | Page header with an Accounts/Ageing switch; filters show "Paid / Partially paid / Due soon…" instead of codes; summary tiles in even rows with dates in one tile; flat sub-panels; small row buttons |
| **Purchases** | Header with a segmented section switch; pay card aligned |
| **Expenses** | Header with a "New expense" action; empty-state rows; **recurring form requires a category (no default)** |
| **Stock / Products / Admin** | Header plus responsive card grid (Admin no longer squeezes 6 cards into narrow columns; the CSV and scale inputs are no longer clipped); empty state for stock on hand |

| **Accounting / Refund** | Header. The Arabic provisional warning is now fully translated |

**Inline styles:** 177 → 105. The rest are mostly single-use layout widths. No CSS override pile was added: one stylesheet with tokens; the overrides are media queries only.

## 12. Remaining visual issues

- Several pages still use one long vertical layout: Accounting, the Customers account page, Expenses. They are now consistent, but tabs within the page would shorten them.
- 105 inline styles remain, mostly single-use widths; a further pass could move them into utility classes.
- The cart's empty space under few items is unchanged (a design choice: the cart can grow).
- Date inputs use the Windows locale format (dd/mm/yyyy), set by Chromium, while the app shows ISO dates elsewhere.
- Icons: only status badges use icons (inline SVG, one style). No icon library is installed, and none was added.
